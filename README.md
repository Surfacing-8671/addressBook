# Balancer tokenlists

This is a general purpose tokenlist generation app that Balancer uses to
generate it's
[tokenlist](https://github.com/balancer/tokenlists/blob/main/generated/balancer.tokenlist.json).

## Make changes to the Balancer tokenlist

To make changes to the balancer tokenlist edit the files in
[src/tokenlists/balancer](https://github.com/balancer/tokenlists/tree/main/src/tokenlists/balancer).

1. `metadata.ts` - Edit this to change the highlevel tokenlist metadata.
1. `tokens/<network>.ts` - Edit this to add or remove tokens from the generated
   tokenlist. E.g Tokens for Arbitrum go in `tokens/arbitrum.ts`, tokens for
   Ethereum go in `tokens/ethereum.ts`.
1. `overwrites.ts` - Edit this to overwrite any token data that is incorrect
   when generated automatically.

Once changes are made, the tokenlist can be regenerated by running:

```shell
npm run generate
```

This updates the generated file at `/generated/balancer.tokenlist.json`

**However, you do not need to run this command locally. Simply make changes to
the mentioned files and merge them with the `main` branch. Following this, an
autogenerated PR will be created to update the generated tokenlist files.**

## Screen tokens for transfer tax

Fee-on-transfer and rebasing tokens break integrations that assume the amount
sent equals the amount received, so screen new additions before they land in the
list:

```shell
npm run token:check-tax                       # every Robinhood token
npm run token:check-tax -- --manual           # only tokens/manual.ts
npm run token:check-tax -- 0xabc... 0xdef...  # specific addresses
npm run token:check-tax -- --verbose --json report.json
```

By default the check only reports. Add `--write` to actually remove failing
tokens from `tokens/manual.ts` and `tokens/robinhood.ts`, so they never reach
the generated list:

```shell
npm run token:check-tax -- --write
npm run generate
```

`--write` removes `TAXED` and `REBASING` tokens. `SUSPICIOUS` and `UNKNOWN` are
left alone, because neither is evidence against a token - add
`--prune-suspicious` if you want the suspicious ones dropped too.

Note that `tokens/robinhood.ts` is regenerated by `npm run robinhood:sync`, so a
token removed from it comes back if the RHJ feed still lists it. Re-run the
check after each sync.

Nothing is broadcast on chain. The checker replaces the code at a real holder's
address with `contracts/TaxProbe.sol` using an `eth_call` state override, so
`msg.sender` inside the token's `transfer()` is that holder and their balance is
genuine. The probe reads balances and `totalSupply` either side of the transfer,
and any shortfall between the amount sent and the amount received is the tax.

Fee exemptions are common, so each token is probed from three different EOA
holders plus toward and away from the largest contract holder (usually the LP
pair) to cover the sell and buy directions. The worst result wins. The runtime
bytecode is also scanned for tax and rebase function selectors, which catches
tokens whose sampled holders all happened to be fee-exempt.

Verdicts are `CLEAN`, `TAXED`, `REBASING`, `SUSPICIOUS` (no tax measured but tax
machinery present - worth a human look) and `UNKNOWN` (nothing to simulate, e.g.
a token with zero supply). The command exits non-zero if anything is judged
`TAXED` or `REBASING`, so CI can gate on it.

The public RPC rate limits hard enough to make a full scan take over ten
minutes, so point the checker at a local archive node when you have one:

```shell
ROBINHOOD_RPC_URL=http://127.0.0.1:8547 npm run token:check-tax
```

## Create a new tokenlist

Although this repo is primarily for maintaining the balancer.tokenlist.json
file, it can be forked and used to generate any kind of tokenlist. Simply run:

```shell
npm run tokenlist:create my-new-tokenlist
```

This will create a new template tokenlist in `/src/tokenlists` with the
necessary files. Then, just add token addresses to the `tokens.ts` file and run
`npm run generate` to generate your tokenlist json file.

## Development

To run the `generate` command locally or in the Github actions of a fork you
will need to add these ENV variables:

```
DRPC_KEY=xxx
INFURA_KEY=xxx
ALCHEMY_KEY=xxx
COINGECKO_API_KEY=xxx

```

You'll need to sign up for each of those services to get keys:

- https://www.infura.io/
- https://www.pokt.network/
